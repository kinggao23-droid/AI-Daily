## 1. 今日要闻

### 🔴 要闻一：Subquadratic 以 $2900 万种子轮出场，SubQ 模型号称 1200 万 token 上下文窗口

**平台**：Subquadratic（🆕 新发现平台）  
**时间**：2026-05-05  

迈阿密初创公司 Subquadratic 携 2900 万美元种子轮融资亮相，发布首个完全次二次（subquadratic）架构的前沿大模型 SubQ。投资方包括 Tinder 联合创始人 Justin Mateen、前软银愿景基金合伙人 Javier Villamizar，以及 Anthropic、OpenAI、Stripe 和 Brex 的早期投资人。

**关键数据**：
- 上下文窗口：**1200 万 token**（对比 Claude 4 Opus 约 20 万、GPT-5 约 100 万）
- 官方声称在 100 万 token 时比主流前沿模型**快 50 倍、便宜 50 倍**
- 在 1200 万 token 满窗口时，计算需求降低约 **1000 倍**
- 估值：**5 亿美元**（种子轮阶段）
- 团队规模仅 **4 人**

**风险提示**：  
该公司**尚未发布完整技术报告、未开源权重、无同行评审**。此前类似的次二次架构（Mamba、RWKV、DeepSeek Sparse Attention）在前沿规模上均未超越 Transformer。VentureBeat 等媒体已对其性能声明提出质疑，建议持观望态度。

**影响分析**：如果 SubQ 的性能声明属实，将对依赖长上下文处理的企业场景（全代码库分析、长文档审查、多轮对话记忆）产生颠覆性影响。但在独立基准测试验证之前，不建议纳入正式选型。

### 🔴 要闻二：AWS Bedrock AgentCore Payments 细节持续发酵——AI Agent 进入「能花钱」时代

**平台**：AWS Bedrock  
**时间**：2026-05-07 发布，本周持续报道  

AWS Bedrock AgentCore Payments 在 5 月 7 日发布后持续引发行业讨论。这是**首个由主流云厂商原生提供的 AI Agent 自主支付方案**，与 Coinbase 和 Stripe 联合构建。

**核心机制（通俗解释）**：  
相当于给 AI Agent 开了一个受控的"数字钱包"。Agent 在执行任务过程中遇到付费资源（API、网页内容、其他 Agent 的服务），无需中断推理流程，自动完成协议协商、支付和重试。企业可设定每次会话的支出上限。

**关键技术参数**：
| 指标 | 数据 |
|------|------|
| 结算网络 | Base 网络（Coinbase L2） |
| 结算币种 | USDC（稳定币） |
| 结算时间 | 约 **200 毫秒** |
| 单笔交易成本 | **不到 1 美分** |
| 支付协议 | Coinbase x402（HTTP 原生支付协议） |
| 钱包方案 | Stripe Privy Wallet |
| 可用区域 | 美东、美西、欧洲（法兰克福）、亚太（悉尼） |

**早期客户**：Warner Bros. Discovery 正在测试用于高级内容（含直播体育和娱乐大片）的 Agent 驱动交易。

**影响分析**：Agent Payments 标志着 AI Agent 从「只能回答问题」升级到「能自主执行商业交易」。对于构建端到端自动化工作流的企业，这意味着 Agent 可以自动采购数据、调用付费 API、订阅外部服务，形成真正的闭环自动化。Azure 和 Google 目前无对标能力。

## 5. 对产品经理的启示

### 1）Agent 支付能力正在成为平台差异化的新战场

AWS 率先推出 Agent Payments，意味着 AI Agent 不再局限于"回答问题"和"执行操作"，而是可以**自主参与商业交易**。产品经理在规划 Agent 工作流时，应将"Agent 需要花钱完成的步骤"纳入流程设计，同时建立**支出治理机制**（预算上限、审批规则、异常告警）。

**建议**：如果你的产品涉及 Agent 调用付费 API 或采购外部数据，优先评估 AWS Bedrock AgentCore Payments 的适用性；其他云平台短期内无对标方案。

### 2）超长上下文正在进入"百万级"常态，但要警惕炒作

SubQ 声称 1200 万 token 上下文，但缺乏独立验证。实际落地时，Qwen3.6-Plus 已默认支持百万 token，Claude 4 系列支持 20 万 token。对于需要处理大量文档的企业场景，**百万级上下文已经可用且经过验证**——不需要为未经证实的超长上下文支付溢价。

**建议**：选型时优先考虑有独立基准测试验证的模型（如 RULER、NIAH），而非厂商自报的上下文长度数字。

### 3）「采用率高、部署率低」是当前 Agent 落地的核心矛盾

79% 的企业已采用 AI Agent，但仅 2% 完全部署。这意味着**可靠性和可观测性**是阻碍规模化的关键因素，而非模型能力本身。

**建议**：在模型选型之外，同等重视可观测性平台的选择（Langfuse、Arize Phoenix、Braintrust）。优先投入 Agent 行为监控、异常检测和人工干预机制的建设，而非追求最新最强的模型。

### 4）国内平台价格战持续，企业客户可借势降低成本

阿里云百炼 AI 焕新季提供万亿级 Token 补贴（企业最高 2000 元），火山引擎每日免费 200 万 token。对于处于 PoC 或小规模部署阶段的企业，可以**同时申请多家平台的优惠额度**，用实际工作负载做对比测试。

**建议**：在 5 月 20 日前申请阿里云百炼企业新客补贴；同步对比火山引擎豆包的免费额度是否满足测试需求。

### 5）MoE 架构成为国内大模型的主流技术路线

腾讯混元 Hy3（2950 亿总参/210 亿激活）、百度文心 Ernie-5.0（2.4T 总参/3% 激活）、华为盘古 Ultra MoE（7180 亿总参）均采用 MoE 架构。MoE 的核心优势是**用更少的计算资源驱动更大的模型容量**（通俗比喻：一个公司有 100 个专家，但每个问题只需 3-5 个专家协作回答，不必全员出动）。

**建议**：MoE 架构对推理成本的降低有直接传导效应，选择国产模型时优先关注"激活参数量"而非"总参数量"——激活参数决定推理成本，总参数决定能力上限。
