### 🔥 要闻一：vLLM v0.24.0 发布——DeepSeek-V4 深度优化，多硬件性能全面提升

**平台**：vLLM（开源推理引擎）

**具体内容**：6月30日，vLLM 发布 v0.24.0 版本，包含 408 个 commits，来自 200 位贡献者（63 位新贡献者）。核心更新：

| 更新项 | 具体内容 | 性能提升 |
|--------|---------|---------|
| DeepSeek-V4 优化 | 稀疏 MLA 元数据与 V3.2 解耦、TRTLLM-gen 注意力内核、EPLB 支持 Mega-MoE、滑动窗口 KV 缓存选择性前缀保留 | 推理吞吐显著提升 |
| MRv2 默认扩展 | Model Runner V2 现已默认用于 Llama 和 Mistral 密集模型（此前仅 Qwen3） | 启动速度与内存占用优化 |
| NVIDIA FP8 优化 | FP8 FlashInfer 注意力用于 ViT、Triton MoE 后端 Hopper 默认启用、CUTLASS FP8 scaled-mm 填充绕过 | +20% |
| MoE 预分配优化 | MoE-permute 缓冲区预分配 | +9%–14% |
| AMD ROCm 支持 | ROCm 7.2.3、AITER v0.1.13.post1、RDNA3 原生 W4A16 与 fused-MoE W4A16 HIP 内核 | 新增硬件支持 |
| Intel XPU 支持 | 序列并行支持、torch-xpu 2.12、DeepSeek-V4 注意力/MoE 路径 | 新增硬件支持 |
| 量化增强 | 在线 FP8 per-token-per-channel（PTPC）量化，modelopt_mixed 扩展至 Ampere/SM80-86 和 Turing/SM75 | 更广泛 GPU 兼容性 |

**通俗解释**：想象 vLLM 是大模型的"高速公路"，这次升级相当于在高速公路上增加了更多车道（MRv2 扩展）、优化了最复杂路段的交通调度（DeepSeek-V4 优化），同时让更多品牌的汽车（AMD、Intel 芯片）也能上高速。

**影响分析**：vLLM v0.24.0 的多硬件支持策略值得关注——不再只是 NVIDIA 的天下，AMD ROCm 和 Intel XPU 的原生支持意味着企业在自建推理基础设施时有了更多芯片选择，有助于降低硬件锁定风险和采购成本。DeepSeek-V4 的深度优化也反映了中国大模型在开源推理生态中的影响力持续增强。

### 🔥 要闻二：华为 openPangu-2.0-Flash 正式开源上线（920 亿参数）

**平台**：华为云盘古

**具体内容**：6月30日，华为正式将 openPangu-2.0-Flash 模型开源上线。这是华为在 HDC 2026 大会上宣布的 7 大组件逐步开源计划的首批交付。

首批开源内容（6月30日已上线）：
- **Flash 模型权重**：920 亿总参数（92B），60 亿激活参数（6B），512K 上下文窗口
- **基础推理代码**
- **训练和推理算子**

后续计划：
- **7 月**：Pro 版模型权重（5050 亿总参数，180 亿激活参数）和基础推理代码
- **下半年**：预训练代码、后训练代码等完整训练栈

余承东还透露，计划今年秋天推出 30B 参数的端侧盘古大模型，将在麒麟手机芯片上运行。

**影响分析**：openPangu 2.0 是首个同时开放训练算子的国产大模型，对"国产芯片 + 国产模型"全栈替代具有标志意义。但 Flash 版 6B 激活参数在效果上面临 Qwen3.7、DeepSeek-V4 等竞品的挑战，实际生产能力需等社区基准测试验证。对于使用昇腾芯片的政企客户，这是目前唯一的全栈国产方案。

- [36氪：openPangu-2.0-Flash 模型正式开源上线](https://www.36kr.com/newsflashes/3875157845497091)

### 🔥 要闻三：Databricks DAIS 2026 大会核心公告全面梳理——Agent Bricks 生态大爆发

**平台**：Databricks

**具体内容**：Databricks Data + AI Summit 2026 于 6月15-18日在旧金山 Moscone Center 召开，超 3 万人参会。大会收官后各项公告进入落地阶段，核心发布：

| 产品 | 状态 | 核心能力 |
|------|------|---------|
| **Genie One** | GA | 全能 Agentic 助手，跨结构化/非结构化数据生成文档和报告，支持 Web/iOS/Android、定时任务和告警 |
| **Genie Ontology** | Preview | 自改进语义上下文引擎，自动提取表关系、列指标和查询频率信号 |
| **Agent Bricks** | 扩展 | 已构建超 10 万个 Agent，年处理超 1 千万亿（1 quadrillion）tokens；新增 Claude Code SDK、LangGraph、Agno、CrewAI、OpenAI Agent SDK 支持 |
| **Omnigent** | Beta | 开源（Apache 2.0）元编排框架，管理不同框架的编码 Agent，带成本预算和共享会话，由 Unity AI Gateway 治理 |
| **LTAP** | Preview | 湖仓 OLTP/OLAP 融合，消除 CDC 管道、ETL 作业和数据同步 |
| **Lakebase** | Preview | 新一代数据基础设施层 |

**通俗解释**：Databricks 正在把自己从一个"数据分析平台"变成一个"AI 员工管理平台"。Genie One 像一个能理解公司所有数据的 AI 同事；Agent Bricks 像一个 AI 员工的"人力资源系统"，帮你招聘、管理、监督上百个 AI 助手；Omnigent 则是一个"总调度"，让不同类型的 AI 助手协同工作。

**影响分析**：Agent Bricks 年处理超 1 千万亿 tokens 的数据规模，以及 10 万+ Agent 的构建量，标志着 Databricks 在企业 Agentic AI 领域已形成规模化落地。对标 Snowflake 的 CoWork/CoCo，Databricks 的差异化在于开源生态（Omnigent Apache 2.0）和多框架兼容性。

### Snowflake vs Databricks：Agentic AI 平台对决

两大数据平台在 6 月的峰会上都将"Agentic 企业"作为核心叙事，但策略差异明显：

| 维度 | Snowflake | Databricks |
|------|-----------|------------|
| 核心产品 | CoWork（个人 Agent）+ CoCo（编码 Agent） | Genie One（全能 Agent）+ Agent Bricks（Agent 平台） |
| 开放性 | CoCo 支持外部数据源（Databricks、AWS Glue、Postgres） | Omnigent 开源 Apache 2.0，支持 5+ Agent 框架 |
| 模型合作 | 深度绑定 Anthropic Claude | 多模型策略（Claude、GPT、Llama 等） |
| 治理 | 内置数据治理 | Unity AI Gateway + Unity Catalog |
| 上下文增强 | Cortex Sense（Private Preview，准确率 24%→83%） | Genie Ontology（自动语义提取） |
| 客户规模 | CoCo 覆盖 50%+ 客户（7,100+ 账户） | Agent Bricks 已构建 10 万+ Agent |

## 4. 新兴平台雷达

### 🆕 Seltz — AI Agent 专用搜索引擎

- **定位**：为 AI Agent 重新设计的搜索引擎，区别于面向人类的传统搜索
- **融资**：1250 万美元种子轮（6月24日），Speedinvest + B Capital 领投
- **核心差异**：AI Agent 发出长精确查询、数百个并行搜索请求，需要机器可读的可引用信息，而非为吸引人类点击的摘要片段
- **团队**：15 人（其中仅 6 人全职），2025 年 10 月注册于美国
- **参考链接**：[Fortune：Seltz 融资报道](https://fortune.com/2026/06/24/exclusive-seltz-a-startup-rebuilding-web-search-for-ai-agents-raises-12-5-million-in-seed-funding/)

**为什么值得关注**：随着 Agentic AI 从概念走向规模化（Databricks 10 万+ Agent、Snowflake 50%+ 客户使用 CoCo），Agent 的"基础设施层"——包括搜索、工具调用、记忆——正在成为新的投资热点。Seltz 切入的是 Agent 搜索这一细分赛道。

### 🆕 Databricks Omnigent — 开源 Agent 元编排框架

- **定位**：管理和编排来自不同框架（LangGraph、CrewAI、OpenAI Agent SDK 等）的编码 Agent
- **协议**：Apache 2.0 开源
- **差异化**：统一成本预算控制、共享会话、跨框架 Agent 调度
- **参考链接**：[Databricks Blog：Agent Bricks at DAIS 2026](https://www.databricks.com/blog/agent-bricks-dais-2026)

**为什么值得关注**：当企业同时使用多个 Agent 框架时，如何统一管理和控制成本是痛点。Omnigent 填补了"Agent 的编排层"这一市场空白，且以开源策略对抗 Snowflake 的封闭生态。

## 5. 对产品经理的启示

### 1. "Agentic 企业"已从概念进入基础设施竞争阶段

Databricks（10 万+ Agent 构建量）和 Snowflake（50%+ 客户使用 CoCo）的数据表明，Agent 不再是实验性功能，而是企业正在规模化部署的生产能力。产品经理在规划 2026 H2 路线图时，应将 Agent 编排、成本控制和治理作为核心功能而非附加模块。

### 2. 多硬件推理成为选型新维度

vLLM v0.24.0 同时支持 NVIDIA、AMD 和 Intel 三大芯片平台，打破了 NVIDIA 的推理垄断。对于自建推理基础设施的企业，建议：
- 评估 AMD MI300X 和 Intel Gaudi 3 作为备选方案
- 在采购谈判中利用多硬件竞争获取更优价格
- 关注 vLLM 在非 NVIDIA 平台上的实际性能基准测试数据

### 3. 国内大模型"价格战"进入补贴阶段，但需警惕补贴到期

阿里云百炼（OPC 计划最高 100 万元补贴）和火山引擎（最低 2.5 折）的激进定价策略有利于降低企业试用门槛，但火山引擎 6月30日优惠到期提醒我们：**基于补贴的定价不可持续**。建议：
- 利用当前窗口期完成 PoC 和基准测试
- 在选型评估中将"补贴后价格"和"常规价格"分开测算
- 关注 7 月各平台是否推出新一轮优惠

### 4. 华为开源盘古 2.0 为国产化替代提供新选项

对于政企客户和受出口管制影响的企业，openPangu 2.0 + 昇腾芯片提供了"全栈国产"方案。但需注意：
- Flash 版 6B 激活参数在效果上可能不及 Qwen3.7（激活 21B）等竞品
- 社区生态和工具链成熟度远不及 Qwen 和 DeepSeek
- 建议等待 7 月 Pro 版开源后再做全面评估

### 5. 观测工具（Observability）进入"去锁定"时代

LangSmith 新增 OpenTelemetry 支持意味着它不再只服务 LangChain 用户；Langfuse 的 ClickHouse 全文搜索将自托管性能提升 40 倍。两者在功能上日趋趋同，选型关键转向：
- **自托管需求**：Langfuse 优势明显（完全开源）
- **生态集成**：LangSmith 与 LangChain/LangGraph 的原生集成仍更紧密
- **成本敏感**：Langfuse Code Evaluators 的零 token 评估值得关注
