### 要闻二：Microsoft Foundry 托管 Agent 正式可用（GA），Routines 与 Toolboxes 进入公测

**平台**：Microsoft Foundry（原 Azure AI Foundry）
**时间**：2026 年 7 月上旬 GA

Microsoft Foundry 的**托管 Agent（Hosted Agents）** 正式进入 General Availability，核心能力包括：

| 功能 | 说明 | 状态 |
|------|------|------|
| **Hosted Agents** | 沙箱化 Agent 运行时，支持状态管理、文件系统访问、多框架兼容 | **GA** |
| **Routines** | Agent 可按计划或触发器自动运行（类似 cron 任务） | Public Preview |
| **Toolboxes** | 一个托管 MCP 端点管理一组工具，统一认证与治理 | Public Preview |
| **Voice Live** | 实时语音对话路径 | Public Preview |
| **Teams / M365 Copilot 发布** | Agent 可直接发布到 Teams 和 Microsoft 365 Copilot | GA |

Toolboxes 的核心价值在于：工具注册一次，运行时自动发现——不需要在每个 Agent 里硬编码工具连接。这与 MCP（Model Context Protocol）的设计理念一致。

**影响分析**：Foundry 成为三大云中第一个将 Agent 运行时做到 GA 的平台（AWS AgentCore 仍在 Preview，Google Agent Development Kit 仍需自托管）。Routines 功能让 Agent 从"被动响应"变为"主动执行"，对企业自动化场景（如定时报表生成、定期数据校验）意义重大。Toolboxes 则解决了企业级 Agent 的工具碎片化问题。

## 5. 对产品经理的启示

### 1. GPT-5.6 三档体系改变模型选型逻辑

OpenAI 的 Sol / Terra / Luna 三档命名体系意味着"版本号"时代的终结。产品经理在做模型选型时，应将路由策略纳入架构设计——简单查询用 Luna（$1），复杂推理用 Sol（$5），日常任务用 Terra（$2.5）。建议在 LLMOps 平台中配置基于任务复杂度的动态路由规则，而非绑定单一模型。

### 2. Agent GA 窗口打开，Microsoft Foundry 先发

Foundry 托管 Agent GA 是一个重要信号。如果你的企业已在 Microsoft 生态（Azure AD、Teams、M365），现在是评估 Foundry Agent 的最佳时机——GA 意味着 SLA 保障。Routines 功能对"定时执行"场景（如每日数据校验、周报生成）尤其有价值。AWS AgentCore 预计将在未来 1-2 个季度 GA，可作为备选。

### 3. "人+AI"交付模式值得借鉴

AWS、Anthropic、OpenAI 三家同时投入"前线工程师"模式，说明 AI 产品的落地瓶颈在**最后一公里执行**而非技术能力。对内部 LLMOps 平台来说，这意味着：
- 不要只做"工具"，要做"可交付的解决方案"
- 提供模板化的 Agent 工作流，降低用户从零开始的门槛
- 考虑内部"AI 教练"或"AI COE"团队，扮演企业内部的 FDE 角色

### 4. 国产模型性价比窗口持续扩大

阿里云百炼 GLM-5.2 Fast mode 降价 20%，叠加腾讯 Hy3 的 1 元/百万 token 定价、Qwen3.7-Max 的国产第一表现，国产模型在成本和能力上的竞争力持续增强。建议在非数据合规敏感场景中，将国产模型纳入路由候选池，降低整体推理成本。

### 5. 可观测性成为标配

Braintrust $80M 融资、Snowflake Cortex Agent 评估的 GPA 框架、MLflow AI Gateway 的统一追踪——可观测性从"锦上添花"变为"必备基础设施"。如果你的 Agent 还没有端到端的追踪和评估体系，这应该是下一个季度的优先事项。
