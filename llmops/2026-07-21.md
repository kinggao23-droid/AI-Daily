**平台**：Snowflake Cortex AI
**时间**：7 月中旬进入 Private Preview

## 5. 对产品经理的启示

### 1. 国内模型 API 价格战进入「细颗粒度」阶段

阿里云百炼对 GLM-5.2 Fast mode 单独降价 20%，说明价格竞争已不再是简单的"全面降价"，而是针对特定模式（快速模式 vs 标准模式）的差异化定价。**建议**：在产品架构中区分"实时交互"和"批量处理"两类调用路径，分别对接不同的计费模式，可以降低 30–50% 的推理成本。

### 2. 数据平台正在成为 AI Agent 的天然底座

Snowflake 推出 Cortex Sense、Cortex Code 接入 AWS Glue / Databricks / Postgres，方向很明确：让数据平台成为 AI Agent 的"家"。**建议**：如果企业已经重度使用某个数据平台（Snowflake / Databricks / BigQuery），优先评估该平台原生的 AI Agent 能力，而非另建独立的 LLMOps 栈。平台内的上下文共享和权限复用，比跨系统集成高效得多。

### 3. 开源推理引擎的稳定性仍需关注

vLLM v0.25.1 因张量并行 Bug 被撤回，提醒我们开源推理框架的迭代速度快，但质量保障机制仍不够成熟。**建议**：生产环境中使用 vLLM 等开源引擎时，建议锁定经过验证的稳定版本（如 v0.25.0），设置至少 1 周的灰度观察期再升级，并建立自动化的推理性能回归测试。

### 4. LLM 可观测性平台趋向融合

Langfuse（Monitor + Slack/Webhook 告警）、Braintrust（一站式模型网关 + 评估）、Arize Phoenix（50+ 内建评估指标）正在相互靠拢。**建议**：选型时不要只看单一功能（如 Trace 或 Eval），而是评估平台的闭环能力——能否从"发现问题"直接触发"修复流程"。Langfuse 的 GitHub Actions 集成就是这种闭环的体现。
